# DeskBar 产品范围

状态：初始设计；2026-10-16。

## 用户任务

用户希望在电脑旁放一块 Android 屏幕，查看正在运行的任务、账号额度和 API 用量，并快速回到电脑上的会话或打开常用入口。安装与连接应由两端 App 完成，用户不需要搭建基础设施。

基本流程是：安装桌面 Agent → 安装 Android App → 发现电脑并配对 → 选择共享内容 → 组成自己的页面 → 自动重连。

## 首版能力

| 能力 | 行为 |
| --- | --- |
| 会话 | 显示近期任务与状态；经授权后在来源电脑打开 |
| 账号额度 | 显示剩余额度、重置时间和采集状态 |
| API 用量 | 作为可选来源显示费用、Token、TPM 等信息 |
| 快捷入口 | 桌面配置应用与 URL；Android 提交入口 ID |
| 页面 | 新建、命名、排序、删除，左右横滑切换 |
| 组件 | 按需添加、重复添加、隐藏、移动、缩放、临时铺满 |
| 显示参数 | 会话卡片目标宽高与间距；入口图标大小与横纵间距 |
| 屏幕适配 | 横竖屏、全屏、常亮与安全区；各方向独立保存摆放 |
| 连接 | 发现、扫码或配对码、IP 变化后的身份核验与重连 |

首个可用闭环优先 macOS 与 Android。Windows 使用同一产品结构，待平台能力与安装路径验证后交付。首版先完成单电脑连接；稳定身份和资源模型允许后续增加多电脑。

## 页面原则

页面只是一组组件，没有「任务布局」「启动器布局」等类型。用户可以创建只放快捷入口的一页，也可以在一页放多个会话组件。每个实例独立保存参数。

关闭会话组件只是改变显示，不停止电脑上的任务。切换用量来源也不会改变快捷入口的执行电脑。App 内组件与 Android 系统桌面组件是不同展示面，不共用尺寸规则。

## 离线体验

- 互联网断开而局域网仍可用时，本机会话与电脑打开动作仍应工作。
- 额度和 API 用量依赖上游；刷新失败保留缓存并显示过期状态。
- Host 睡眠、Agent 退出或网络隔离时显示离线；不会因发现过这台电脑就显示在线。
- 页面编辑不依赖网络；动作断线后不排队补发。

## 本次提取范围

保留已有工作台、点阵、主题、全屏和设备适配中适用的能力。Android 本机入口仍由 Android 定义与执行。系统桌面组件的后台刷新单独验证，不承诺无限实时连接。

收件箱、跨端消息与附件、OLED、Core Console、MQTT 投影调度不属于这次提取。DeskBar 不承担通用设备编排。

## 成功条件

新电脑和新 Android 仅安装两端即可完成配对，无需额外服务器、MQTT、数据库或证书导入。换 IP 后仍识别原电脑；错误公钥不能继承配对。页面和组件可恢复，远程动作能区分已接收、执行失败与结果未知。
