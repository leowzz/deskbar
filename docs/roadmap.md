## 阶段 1：连接与配对闭环

首先验证普通用户能连上电脑，尤其是无摄像头 Android 的配对码路径。

产物：可构建的桌面与 Android 最小工程；稳定 Host 身份与安全存储；query / offer；认证 HTTPS / WSS；扫码与 PAKE 配对原型；最小快照。

验收：

- 两端安装后直接发现与配对，无需 Core 或 Broker。
- 换 IP 后通过原公钥重连；同名电脑、错公钥无法继承信任。
- 端口占用、多播受阻、权限拒绝能给出对应路径。
- 过期配对与撤权生效；无摄像头路径有实际验证。

该阶段落定产品组地址、默认端口、应用标识、依赖版本、PAKE 库和原生桥接方式。先记录发现耗时、成功率与发包量，再设默认阈值。

## 阶段 2：单电脑工作台

产物：从 Orbit 提取会话、额度、API 用量与入口目录；Android WorkbenchStore；有限动作执行与结果；电脑端页面和组件编辑、逐设备原子保存与布局同步。

验收：

- Android 脱离 InboxController，桌面运行时脱离 MQTT / Orbit wire。
- 无上游账号或某来源失败，不影响其他组件。
- 会话打开与快捷入口执行回到正确 Host，能区分 accepted 与实际结果。
- 页面没有类型，同类组件可重复，实例参数独立。
- 横滑不误执行动作；编辑、旋转、保存、取消与进程重启符合工作台设计。
- 重复提交、丢响应和执行中退出符合命令去重与未知结果规则。

## 阶段 3：安装与 Android 生命周期

产物：macOS 签名与公证安装包、独立 Android 包、更新验证、权限引导、前后台与系统组件缓存策略。

验收：新电脑与新 Android 只安装两端即可使用。覆盖普通手机、低高度横屏、Android 9 设备、新版 Android、系统大字号、安全区、常亮、息屏与系统回收。

App 不可见时的持续刷新单独决定并验收；现有声明不能代替新产品的平台验证。

## 阶段 4：Windows 与多电脑

产物：Windows 平台 Adapter、签名安装包、防火墙与登录启动；多 Host 分组与来源选择。

验收：Windows 凭据存储、Codex 发现 / 深链、应用打开和图标取得均有真机证据。同名资源仍执行到正确电脑；一台离线不影响其他连接；相同账号额度不累加。
