# 页面与可选组件

状态：电脑负责页面和组件编辑、自动更新；Android 负责展示与操作。2026-10-16。

工作台由有序页面组成，每页可添加任意组件，同类组件可以重复添加。组件拥有独立的来源绑定、横竖屏摆放与显示参数。初始提供「总览」「任务」「应用」三页，新页面为空白，至少保留一页。

## 双端分工

| 电脑端「屏幕编辑」 | Android 工作台 |
| --- | --- |
| 选择设备，管理页面、组件与来源 | 接收电脑更新的布局 |
| 新建、改名、排序、删除页面 | 左右滑动或键盘切页 |
| 添加、隐藏、恢复、移动、缩放组件 | 组件内容上下滚动，打开已授权会话与入口 |
| 调整卡片宽高、图标大小、间距、数量、快捷入口行数和对齐方式 | 主题、全屏显示、锁定旋转、重连、断开连接 |
| 预览、布局调试、撤销 / 重做、自动更新 | 离线查看上次布局和数据，禁止远程动作 |

移动端右上角的「设置」和长按空白 / 非交互内容均打开基础设置，不进入编辑。全屏后设置入口仍保留。页面和组件的编辑入口只出现在电脑端。

## 编辑与实时预览

在电脑的「屏幕编辑」选择设备，直接点击画布或左侧列表中的组件编辑属性，无需切换编辑模式。左侧常驻页面与本页组件：点击切页、拖动页面握柄排序，页面菜单重命名或删除；组件旁的眼睛按钮隐藏或恢复。顶部「添加组件」直接选择类型，支持重复添加；工具栏提供整理、撤销、重做和完成。每次变更停止操作约 450ms 后自动更新本机布局并下发设备，编辑期间可以继续修改；更新失败保留当前改动，并在后续变更或完成时重试。

编辑器与 Android 共用 Flutter 的 `WorkbenchCanvas`、`WorkbenchWidgetBody` 和布局模型。预览持续读取该设备的授权快照；不会用电脑的全量数据冒充设备可见内容，也不会执行打开动作。React 外壳仅负责设备选择、同源消息桥接和 Tauri 持久化调用。

预览直接使用设备上报的工作台可用宽高（已排除系统安全区和 App 顶栏）、主题和当前页面；电脑端会按设备 ID 保存最近一次宽高，设备暂时离线时继续按该尺寸编辑，首次未上报时才使用 1280 × 720 dp 作为占位。工具栏只选择横屏或竖屏，不展示设备尺寸或字号信息。横竖屏使用同一台设备的长边和短边，不区分固定分辨率，也不提供自定义宽高。预览在电脑窗口中等比缩放，布局仍按设备 dp 计算；「布局调试」默认显示，可关闭；「原始尺寸」仍可滚动画布查看调试标注。预览是同源数据渲染，不是设备截图或视频，组件内部滚动位置不镜像。

编辑器按电脑窗口宽度排布，设备旋转只改变中央画布和当前编辑的横 / 竖屏摆放。编辑区域宽度达到 1000 px 时，左侧固定 220 px 页面与组件列表，右侧固定 300 px 属性，中间画布等比适配；700–999 px 时，右侧以「页面与组件 / 属性」切换；更窄窗口在画布下方切换面板。选中前后保留画布区域，面板不覆盖预览。组件不显示编辑标题条或设置浮窗，选中后显示边框及边缘缩放握柄，整个内容区域都可拖动。切换方向保留选择与当前改动，两种方向独立摆放；属性使用电脑字号，设备字号仅影响预览。属性可直接输入位置、宽高和显示参数，数字输入框右侧提供加一 / 减一按钮；位置与尺寸以当前方向网格为单位，Enter 或离开输入框提交，无效值或空间不足时恢复原值。「布局调试」用淡色透明填充和小边框标出组件区域，并在会话卡片、快捷入口单元、用量内容区及用量内部 item 标注边界和实际尺寸；调试仅影响电脑界面，不写入布局或下发设备。

## 编辑行为

| 操作 | 规则 |
| --- | --- |
| 移动 / 缩放 | 组件整个区域拖动移动，选中后左右 / 下边缘与下角缩放；碰撞时其他组件就近让位，空间不足则保留原布局 |
| 隐藏 / 恢复 | 保留实例与原位置；恢复冲突时提示先整理 |
| 整理本页 | 只重排当前页、当前方向的可见组件 |
| 移到其他页 | 保留 ID、绑定与参数，两种方向均需有空间 |
| 删除页面 | 确认后删除页面及组件，当前改动中可撤销 |
| 自动更新 | 每次变更停止操作约 450ms 后原子更新所有页面并推送给对应设备；编辑期间可以继续修改，失败保留当前改动并在后续变更或完成时重试 |

画布或组件列表选中后，方向键移动一格，Shift + 方向键移动十格；Delete / Backspace 删除组件，Escape 取消选择。⌘ / Ctrl + Z 撤销，⌘ / Ctrl + Shift + Z 或 Ctrl + Y 重做。输入框保留文字编辑快捷键；完成会先提交当前数值输入并等待未完成的自动更新。

横屏使用 48 × 48 网格，竖屏使用 16 × 96 网格；分别记录摆放，实例参数共用。一次拖动和所有碰撞让位占用一条撤销记录。编辑中不能切换设备；切换电脑应用导航后保留当前改动。

会话数量默认 20，可设 1–40。目标卡片宽度决定整数列数，卡片均分整行；完整行铺满开启时，实际高度均分可见高度，否则使用目标高度并内部滚动。卡片目标宽度至少为 120 dp；目标高度在精简模式至少为 88 dp、标准模式至少为 96 dp，达到下限时减一按钮置灰并提示已是最小值。系统大字号会按文字倍率提高运行时最小高度，不整体缩小文字。快捷入口支持固定图标尺寸或「自适应最大」，可设自动或 1–12 行，并选择左对齐、居中对齐、均匀分布或右对齐；自适应最大会在当前组件宽高、标签和间距约束内尽可能放大图标，空间不足时提示在电脑调整组件。

用量组件会按组件可用宽高重新排布内容：默认使用「自适应填充」，主指标随高度放大，进度信息在剩余空间中均匀分布，宽高变化不会只留下空白。电脑端可分别设置「内容布局」（自适应填充、标准、紧凑）和「内容对齐」（顶部、居中、均匀分布、底部）。Token、TPM、统计窗口或额度重置时间通过组件悬浮提示展示，不占用组件布局空间，也不会因为数据刷新改变编辑画布尺寸。组件很小时自动降级为紧凑显示，保留主指标并允许内部滚动。

## 配置与同步

布局结构见 [跨端布局样例](../protocol/layout.example.json)。数组顺序决定页面顺序，实例 ID 不随移动或改名变化。快捷入口的 `iconSize` 可为正数或 `max`（自适应最大），`rows` 可为 `auto` 或 1–12 的整数，`alignment` 可为 `left`、`center`、`spaceEvenly` 或 `right`。用量组件的 `density` 可为 `compact`、`standard` 或 `fill`，`alignment` 可为 `top`、`center`、`spaceEvenly` 或 `bottom`；详细数据使用悬浮提示展示，不写入布局参数。只接受当前布局版本，不迁移 Android 旧本机布局。

- Host 在每个设备记录中保存布局与独立的 `layout_revision`，和许可一起原子写入 `host.yaml`。
- 电脑保存携带预期布局版本，版本冲突拒绝覆盖。来源数据刷新不会造成布局保存冲突。
- 授权快照包含该设备自己的 `layout` 与 `layout_revision`；保存后 WSS 推送，重连接收最新完整快照。
- Android 不读写旧本机布局文件，布局随授权快照由 Keystore 加密缓存。离线可展示；明确撤权清除凭据和缓存。
- Android 切页保留当前运行页面；接收新布局时若当前页仍存在则保留，否则切到电脑配置的默认页。
- 设备每五秒及尺寸 / 页面变化后上报显示状态和已应用布局版本。电脑区分已更新、等待接收和离线；本机更新完成不等于设备已经接收。
- 显示报告不修改布局、不提升权限、不包含凭据或电脑路径。组件隐藏也不停止电脑任务或撤销共享。

## 实现边界与验证

`LayoutWorkspace` 管理不可变文档、当前编辑改动和撤销。电脑编辑入口为 `desktop_editor.dart`，构建为随 Tauri 打包的本地 Flutter Web 资源；CanvasKit、字体均本地打包，不引入独立服务。Android 主入口不启用编辑。旧 `LayoutRepository` 只用于已有编辑器存储测试，不再作为移动端生产配置来源。

两端组件使用本地 Noto Sans SC 字体，减少浏览器与 Android 的文字度量差异。实际系统渲染、安全区、触摸与生命周期仍需真机验收。检查范围与历史证据见 [跨端验证](../tests/README.md)；[HTML 原型](prototypes/workbench.html) 是旧交互探索，不代表当前双端分工。
